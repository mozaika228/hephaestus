# Hephaestus

Hephaestus is a multi-platform AI assistant (web + desktop + mobile) with a modular backend for chat, file analysis, planning, and integrations.

## Repository Layout
- `apps/web` - Next.js web application
- `apps/desktop` - Electron desktop shell
- `apps/mobile` - Flutter mobile client
- `services/api` - Node.js API (chat, files, planner, integrations)
- `services/ai` - FastAPI service (analysis helpers and jobs)
- `services/orchestrator` - FastAPI multi-agent graph orchestrator
- `services/enterprise-java` - Spring Boot enterprise policy/auth service (POC)
- `services/runtime-cpp` - C++ safe execution runtime (POC)
- `packages/shared` - shared constants and utilities
- `infra` - infrastructure assets

## Core Capabilities
- Chat assistant with streaming responses
- Persistent conversations and messages, restored from the API after reopening the web client
- Conversation-linked file records and uploads stored beside the configured persistent database
- Email/password accounts with Argon2id password hashes and revocable, expiring sessions
- User-scoped conversations, messages, files, planner tasks, jobs, and analytics
- Multi-provider model routing (OpenAI, Ollama)
- File ingestion and analysis workflows
- Planner tasks and job queue endpoints
- Enterprise SSO endpoints (SAML start/callback flow scaffold)
- API analytics summary endpoints (request/error/performance breakdown)
- Multi-agent orchestration endpoint (`/orchestrator/run` -> graph service)
- Web/Desktop/Mobile client surfaces

## Architecture
1. Client sends requests to `services/api`.
2. API validates the account session and enforces resource ownership.
3. API routes requests to provider adapters or `services/ai`.
4. API can route high-level tasks to `services/orchestrator` graph execution.
5. API stores users, sessions, conversations, files, tasks, jobs, and analytics in SQLite.
6. Responses are returned as JSON or SSE streams.

## Provider Support
Configured through `services/api/.env`:
- OpenAI (`OPENAI_API_KEY`, `OPENAI_MODEL`)
- Ollama (`OLLAMA_BASE_URL`)

## Local Development
### Prerequisites
- Node.js 20+
- pnpm 9+
- Python 3.10+

### Install
```bash
pnpm install
```

### Run Web + API
```bash
pnpm --filter hephaestus-api dev
pnpm --filter hephaestus-web dev
```

### Run AI Service
```bash
cd services/ai
pip install -r requirements.txt
uvicorn app:app --host 0.0.0.0 --port 8000
```

### API
Use `services/api/.env.example` as baseline.

Important values:
- `HEPHAESTUS_PROVIDER`
- `OPENAI_API_KEY`
- `OPENAI_MODEL`
- `AI_SERVICE_URL`
- `ORCHESTRATOR_URL`
- `ENTERPRISE_JAVA_URL`
- `RUNTIME_CPP_URL`
- `SQLITE_DB_PATH` (set to persistent disk path in production, for example `/var/data/hephaestus.db`)
- `UPLOADS_DIR` (persistent file directory; defaults to a sibling `uploads` directory beside the database)
- `OLLAMA_BASE_URL` and `OLLAMA_MODEL`
- `ENTERPRISE_SSO_ENABLED`
- `SSO_JWT_SECRET`
- `SAML_ENTRY_POINT`
- `CORS_ALLOWED_ORIGINS`
- `RATE_LIMIT_WINDOW_MS`
- `RATE_LIMIT_MAX`
- `PROVIDER_TIMEOUT_MS` (provider request deadline; defaults to 120 seconds)

### Accounts
- `POST /auth/register` accepts an email and a password of at least 12 characters (maximum 128 UTF-8 bytes).
- `POST /auth/login` returns an opaque random bearer token; only its SHA-256 hash is stored in SQLite. Sessions expire after 30 days and can be revoked with `POST /auth/logout`.
- Send `Authorization: Bearer <token>` on API requests from native clients except `/health`, `/auth/register`, and `/auth/login`. The Web client uses an HttpOnly, SameSite=Lax session cookie and credentialed requests.
- Password hashes use Argon2id. Native session tokens are stored using the mobile platform's secure storage; the browser cannot read its session cookie from JavaScript.
- Configure `CORS_ALLOWED_ORIGINS` to the exact web origin(s); do not use `*` for a public deployment.
- Existing pre-authentication records with no owner are intentionally not assigned to the first account. They remain inaccessible until an explicit, safe migration is designed.

### Uploads
- Maximum upload size is 25 MB. The API accepts DOCX, PDF, plain text, Markdown, CSV, common raster images, and selected audio/video formats; the detected file signature is checked for binary formats. DOCX text is extracted locally (up to 60,000 characters) for chat context and direct file analysis; embedded images are not OCR-processed.
- File paths are generated by the server, stored outside the public web root, and never returned by file API responses.
- Deleting a conversation removes its local uploaded files as well as its messages and file records.

## Deployment (Render)
The repo includes `render.yaml` for Blueprint deployment.

Services:
- `hephaestus-web`
- `hephaestus-api`
- `hephaestus-ai`
- `hephaestus-orchestrator`

Current configuration targets free-tier constraints.

## Known Free-Tier Constraints
- Persistent disks are not available on Render free web instances
- SQLite data resets after redeploy/restart if no disk is attached
- Use a persistent disk mounted at `/var/data`; without one, SQLite and uploaded files may be lost on restart or redeploy.
- Video analysis paths requiring system `ffmpeg` may be limited

## Troubleshooting
### `OpenAI response failed`
- Verify `OPENAI_API_KEY` is valid and active.
- Confirm API service uses latest commit in Render.
- Check runtime logs (not deploy logs) in `hephaestus-api`.

### `Cannot GET /`
- Expected on API root URL.
- Use `hephaestus-web` service URL for UI.

### TypeScript build errors in web
- Ensure `typescript` and `@types/react` are installed.
- Redeploy web service after pushing fixes.
